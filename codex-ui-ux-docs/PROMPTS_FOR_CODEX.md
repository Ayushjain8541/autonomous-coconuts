# Ready-to-paste multi-agent prompts

## 1. Full hackathon UI sprint (recommended)

```
Use $hackathon-subagent-director and project roles in .codex/agents to design and implement my app according to my exact instructions and provided Figma screens. First inspect my existing code, flows, constraints and AGENTS.md. Delegate independent pre-implementation analyses to product_flow_strategist, visual_art_director (only if art direction is open), and figma_handoff_specialist (if Figma is available); have design_director reconcile a single visual contract. Assign all overlapping frontend changes to frontend_implementer, who must self-review and run real checks. Then independently review via visual_critique_reviewer, ux_heuristics_auditor, accessibility_auditor, responsive_layout_auditor and functional_ui_tester as appropriate. Use independent_design_challenger for one final user-intent compliance review. Fix P0/P1 and major P2 issues. Do not rewrite backend logic, invent tests, or replace my selected visual style with an AI-default template. Wait for the selected agents' results, then give the changed files, evidence-backed audit, executed checks and remaining risks.
```

## 2. Keep my exact Figma design

```
Use figma_handoff_specialist to translate my selected Figma frames into an implementation contract, design_system_architect for reusable tokens, and frontend_implementer for implementation. After the implementer self-review, independently use visual_critique_reviewer and responsive_layout_auditor to compare the actual render against those frames. If Figma tools cannot read my file, state this and use only available screenshots rather than inventing measurements. Keep my approved layout and aesthetic.
```

## 3. My UI looks off; don't change behavior

```
Audit the current running UI using ui_refactoring_specialist, ux_heuristics_auditor, and visual_critique_reviewer in parallel. Use the user's design intent and existing tokens. Return evidence-tagged findings with P0-P3 severity and a minimal change plan; do not edit code yet. No personal rebranding or backend changes.
```

## 4. Implement scoped polish with independent QA

```
Implement the top confirmed UI fixes using frontend_implementer only, preserving behavior and APIs. Require its self-review and run checks. Then independently review changes with visual_critique_reviewer, accessibility_auditor, responsive_layout_auditor and functional_ui_tester. Ask independent_design_challenger whether any of my design constraints were ignored. Apply critical fixes through the single implementer and rerun relevant tests.
```

## 5. Improve animation only

```
Use motion_interaction_engineer to inspect only motion and interaction feedback in [screen]. Apply Emil Kowalski's design-engineering perspective. Explain which transitions add clarity, which should be removed, reduced-motion behavior and any performance risk. Self-review your suggestions; don't modify unrelated files.
```

## 6. User-first retention audit

```
Use ethical_engagement_analyst to decide whether a meaningful Hook Model is suitable for this product. If yes, map trigger, action, reward, investment while minimizing friction and protecting user agency. Reject dark patterns, fake scarcity, FOMO, or manipulative streaks. Do not modify the app.
```

## 7. Strict design review only

```
Read my UI brief and selected visual references. Spawn independent_design_challenger, visual_critique_reviewer, ux_heuristics_auditor and functional_ui_tester as separate READ-ONLY agents. Ask each to report concrete, independently verified findings and to self-check for unsupported criticisms. Wait for all results, reconcile duplicates and contradictions, and give me an actionable ranked defect list. No edits.
```
