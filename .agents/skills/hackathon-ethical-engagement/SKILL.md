# Ethical engagement and repeat-value review

## Applicability gate
First ask: does the user actually benefit from using this product repeatedly? If it is an emergency service, one-off transaction, sensitive wellbeing tool, or rare administrative workflow, say a habitual loop may be inappropriate. Optimize successful completion, trust and user autonomy rather than repeated use.

## Map the loop (only when appropriate)
1. **Trigger:** What specific, real user need prompts use? Distinguish product-initiated reminders from genuine user needs. Avoid anxiety, insecurity or artificial urgency as drivers.
2. **Action:** What is the smallest valuable task? Are blockers, steps, permissions, or long forms unnecessary?
3. **Reward:** What meaningful outcome does the user receive? Variability is not necessary unless it naturally follows from the product and does not encourage compulsive use. Avoid slot-machine mechanics.
4. **Investment:** What does the user voluntarily add that makes the next session more useful: saved preferences, a completed plan, tracked progress, or collaboration? Avoid manufactured switching costs or dark patterns.

## Review
- Write the expected user benefit, usage frequency, four-phase map, first broken link, and fix.
- Evaluate the first session separately from later sessions.
- Score each phase 0 (missing), 1 (partial), 2 (strong), but **do not** combine these into a pseudo-scientific retention prediction.
- Apply ethics gate: user control of notifications, easy disengagement, no deceptive scarcity, no unnecessary personal data, no exploitation of emotional vulnerability.
- When evidence is missing, mark all retention assumptions as hypotheses, not measured facts.

## Output
| Phase | Observed or hypothesized behavior | Score 0-2 | Friction | Ethical improvement |
Include a 3-sentence recommendation: whether a loop is needed, the highest-value fix, and what user test or metric could validate it. Never add notifications or gamification automatically.
