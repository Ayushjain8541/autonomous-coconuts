# Short handoff format

Each role maintains only its own `P1.md`, `P2.md`, `P3.md` or `P4.md`; create it when there is real work to report. Do not edit another role's handoff or claim work from chat alone.

Include: role and task; branch + commit/PR; delivered behavior; actual setup/run/check commands and results; consumed/produced contract revision; remaining fixtures; missing integrations/blockers and who can resolve them; configuration needs without secrets; next integration action. Name any workflow/skills you actually chose only when useful; no mandatory process attestation is required.

Code ready for review is not integrated. Integrated is not deployed. P4 records the tested combined revision separately. Avoid progress percentages unsupported by observable deliverables.
